# Публикация игры

Один production находится на `81.90.31.214`: `https://game.delopusk.ru`.
`https://game.balkhaev.com` на `49.13.216.63` проксирует запросы к нему по
проверяемому HTTPS. Аккаунты и облачные сохранения находятся в одной SQLite-базе
`/data/prapor/data/accounts.sqlite`; зеркало не содержит копию базы.
Сессии браузера отдельные для каждого домена, с host-only Secure/HttpOnly cookie.

Проект остаётся локальным Git-репозиторием (`remote: null`). Прямой запрос
владельца на публикацию разрешает эту отдельную процедуру. После интеграции
в канонический `main`, проверок из `.devhub/worktree.json` и просмотра приложения:

```powershell
$releaseCommit = git -C F:/code/prapor rev-parse HEAD
powershell -NoProfile -ExecutionPolicy Bypass -File F:/code/prapor/infra/deploy.ps1 -Commit $releaseCommit
```

`-ValidateOnly` проверяет экспорт и Compose без изменений серверов. Скрипт
принимает только полный SHA текущего чистого `main`. Передаваются только
отслеживаемые Git входы сборки и конфигурация `infra`; `.env`, Git-метаданные,
настройки редактора и локальные зависимости не загружаются. Базовые образы в
Dockerfile должны быть закреплены по digest. Образ помечен SHA проверенного
коммита. Временные исходники удаляются после операции, в том числе при ошибке.

Локальный SSH-ключ `C:/Users/user/.ssh/id_ed25519` входит на
`root@deploy.balkhaev.com`. С него используется существующий ключ Coolify
`/data/coolify/ssh/keys/ssh_key@iy9ziufgkgvawjlsyyidpote` для
`root@81.90.31.214`. Ключи не копируются и не выводятся. Оба SSH-перехода требуют
заранее известный host key; отсутствие доступа или изменение ключа останавливает
публикацию. Токен Coolify API и GitHub для этой процедуры не нужны.

Игра запускается отдельным Compose-проектом `prapor-production`, контейнер
`prapor-game`, в существующей сети `coolify`. Его Traefik labels обслуживают
`game.delopusk.ru` и HTTPS-запросы зеркала с Host `game.balkhaev.com`; сертификат
origin запрашивается только для `game.delopusk.ru`. Внешние адреса используют
HTTPS и редирект HTTP. На сервере остаются
`/data/prapor/compose.yaml`, `/data/prapor/release.env` с именем образа и SHA,
а также постоянная папка данных. Порты приложения не публикуются на хосте.
Процесс работает от пользователя Bun без root, с read-only образом; запись
разрешена в папку данных и временную память. База сохраняется между выпусками.
Эта самостоятельная процедура не регистрирует приложение в инвентаре Coolify;
для диагностики используются SSH и Compose.

## Почта аккаунтов

Письма подтверждения адреса и восстановления пароля отправляются через Resend
от `ggpick <noreply@ggpick.club>`. Домен `ggpick.club` подтверждён, отправка
разрешена, отслеживание открытия и переходов выключено. Весь процесс работает
для общих аккаунтов обоих доменов. Абсолютные ссылки строятся только от
`PUBLIC_BASE_URL=https://game.balkhaev.com`, доступного через HTTPS-прокси;
входящий Host не определяет адрес в письме.

Ключ владельца хранится вне Git в `F:/AI/prapor/resend_api_key` с закрытым ACL.
Параметр выпуска `-ResendKeyFile` по умолчанию использует именно этот путь.
Если локального файла нет, выпуск требует уже существующий ключ на production
и сохраняет его значение. Явно указанный, но отсутствующий файл блокирует выпуск.
Ключ не входит в исходники, сборочный контекст, образ, `release.env` или журналы.
Он передаётся отдельно по двум проверенным SSH-переходам и сверяется по SHA-256
без вывода содержимого. Временные копии уходят при очистке scratch.

На origin постоянный путь — `/data/prapor/secrets/resend_api_key`: обычный файл,
владелец `1000:1000`, права `0400`, родительская папка с правами `0700`.
Compose монтирует его read-only в `/run/secrets/resend_api_key`, а приложению
передаёт только `RESEND_API_KEY_FILE`. Автоматическое создание отсутствующего
host-файла запрещено. До замены production проверяются наличие, права и чтение
ключа в отдельном smoke-контейнере без сети; это не отправляет письма.

Сборка и отдельный запуск без почтовой конфигурации остаются возможны.
Настроенный, но отсутствующий или нечитаемый файл ключа должен останавливать
запуск: бесшумно отключать почту в таком состоянии нельзя. Последующие выпуски
не пересоздают ключ. Если значение прежнее, сохраняется существующий файл.
При явно предоставленном новом ключе замена атомарна, новый контейнер получает
новое значение после выпуска. Другие приложения `ggpick` не изменяются.

Сервису достаточно Sending access, ограниченного доменом `ggpick.club`.
Предоставленный владельцем ключ допускает чтение домена. Это указывает на Full
access: Sending access ограничен отправкой, согласно
[документации Resend](https://resend.com/changelog/new-api-key-permissions).
Права провайдера не расширяются этим выпуском. Фактическая доставка подтверждается
только согласованным тестовым письмом; smoke-проверка и статус verified домена
сами по себе её не доказывают.

## Google OAuth

В Google Auth Platform для web-клиента должны быть разрешены точные адреса:

- `https://game.delopusk.ru/callback/auth/google`
- `https://game.balkhaev.com/callback/auth/google`

Клиент использует только `openid email`. Сервер задаёт `GOOGLE_CLIENT_ID`
и `GOOGLE_REDIRECT_URIS`, читает секрет из `GOOGLE_CLIENT_SECRET_FILE`.
При начале входа callback выбирается по проверенному Origin; при возврате его
домен сверяется с реальным Host. `X-Forwarded-Host` не определяет callback.
Одноразовый state привязан к cookie браузера, а обмен кода использует PKCE и nonce.
Секрет, токены Google и код авторизации не передаются в интерфейс и не сохраняются
в журналах. Аккаунты связываются по Google subject; одинаковая почта не разрешает
автоматическую привязку к существующему аккаунту.

Локальный защищённый файл — `F:/AI/prapor/google_client_secret`, параметр выпуска
`-GoogleSecretFile` использует его по умолчанию. Если файл по умолчанию отсутствует,
выпуск проверяет и сохраняет существующий production-секрет. Явно указанный,
но отсутствующий файл блокирует выпуск. Секрет передаётся отдельно от исходников
по проверенным SSH-переходам; SHA-256 проверяется без вывода содержимого.
На origin он хранится в `/data/prapor/secrets/google_client_secret` с владельцем
`1000:1000` и правами `0400`, в папке с правами `0700`. Compose монтирует его
read-only в `/run/secrets/google_client_secret` без автоматического создания.
Повторный выпуск сохраняет файл с прежним значением; новый явно предоставленный
секрет заменяется атомарно. Он не входит в Git, `release.env`, build context,
образ или `dist`.

Configured smoke-контейнер читает оба runtime-секрета без сети, проверяет
доступность Google-входа и выбор callback для двух origins без обращения
к Google. Настоящий вход требует отдельной проверки браузером на каждом домене:
вход, отмена, привязка к существующему аккаунту, повторный вход и доступ
к прежнему прогрессу. Результат callback используется один раз; повтор и чужой
браузер не получают сессию.

Для разработки DevHub использует два отдельных адреса:
`http://127.0.0.1:3020/callback/auth/google` и
`http://localhost:3020/callback/auth/google`. Их наличие в локальной конфигурации
не добавляет их автоматически в Google Auth Platform: для настоящего локального
входа нужно добавить оба в Authorized redirect URIs. Google требует точное
совпадение URI, включая схему, hostname, порт и путь, согласно
[документации web server OAuth](https://developers.google.com/identity/protocols/oauth2/web-server).
Vite проксирует callback на API с исходным Host.

## HTTPS-зеркало

Зеркало — отдельный Compose-проект и контейнер `prapor-game-mirror`.
Конфигурация находится в `/data/prapor/mirror/`, собственный маршрут Traefik —
`/data/coolify/proxy/dynamic/prapor-game-mirror.yaml`. Nginx принимает только
`game.balkhaev.com`; неизвестный Host получает 421. Upstream фиксирован на
`81.90.31.214`, TLS SNI — `game.delopusk.ru`; сертификат проверяется по CA.
Host сохраняется как `game.balkhaev.com`, чтобы callback Google возвращался
на домен начатого входа. Origin принимает оба точных Host, но ACME-сертификат
origin ограничен `game.delopusk.ru` через `tls.domains`; этот параметр имеет
приоритет над Host rule, согласно
[документации Traefik](https://doc.traefik.io/traefik/reference/routing-configuration/http/tls/overview/).
Origin и Referer сохраняются для проверки точных разрешённых origins самим
приложением. Cookie не переписываются, ответы не кешируются, запросы не
повторяются после ошибки. Лимит тела — 2 MiB, таймаут ответа — 60 секунд.
Существующие зеркала других проектов и настройки Traefik не меняются.

Скрипт проверяет DNS, принадлежность своих контейнеров и приватные адреса
Traefik: `172.18.0.2` на origin и `10.0.1.7` на зеркале. Их изменение требует
пересмотра конфигурации, а не отключения проверок. Nginx заменяет входящий
X-Forwarded-For на IP, полученный только от доверенного локального Traefik.
Production Traefik по умолчанию не доверяет forwarded headers удалённого
зеркала, поэтому ограничитель запросов может видеть один IP для его посетителей.
Приложение также ограничивает попытки по имени аккаунта; общая настройка доверия
Traefik не расширяется ради этой публикации.

После выпуска проверить HTTPS без исключений сертификата, HTTP-редиректы,
главную и ассеты, регистрацию, вход, выход и восстановление по коду на обоих
адресах. Проверить сохранение на одном адресе и загрузку той же игры после
входа на втором. Проверить отказ POST с чужим Origin и Secure/HttpOnly/SameSite
cookie. `/health` и здоровье контейнеров подтверждают запуск, но сами по себе
не доказывают работу аккаунтов.

Для диагностики с управляющего сервера:

```sh
ssh -i /data/coolify/ssh/keys/ssh_key@iy9ziufgkgvawjlsyyidpote \
  -o BatchMode=yes -o StrictHostKeyChecking=yes root@81.90.31.214 \
  'docker inspect prapor-game --format "{{.State.Health.Status}}"; docker logs --tail 30 prapor-game'
docker inspect prapor-game-mirror --format '{{.State.Health.Status}}'
docker logs --tail 30 prapor-game-mirror
```

В случае ошибки скрипт сохраняет действующие контейнеры и данные. Автоматического
отката базы нет. Выпуск ранее проверенного коммита требует его обычного
восстановления через Git, повторных проверок и запуска той же процедуры.
Нельзя удалять постоянную папку или пересоздавать SQLite для исправления запуска.
